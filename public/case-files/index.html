CASE / 01

Teaching an AI agent an entire SaaS platform

2026
Anonymized B2B sales intelligence platform
Four production roles
190 documented flows

Claim under review

An autonomous regression program can be trusted only when completion and evidence are machine-checkable.

240+ skills190 flows4 roles
Evidence manifest
  • Versioned skill files describing selectors, fixtures, required actions, edge cases, and expected outcomes.
  • A progress ledger accounting for each documented flow and its terminal state.
  • Deterministic completion checks rejecting shallow passes, unsupported blocked verdicts, and silent skips.
  • Observed browser actions and outcomes rather than log-only classification.
Systemic change

Move trust out of the prompt.

The agent was surrounded by evidence contracts, deterministic turn-boundary gates, versioned executable knowledge, checkpointed progress, and a watchdog process. Reliability came from the surrounding system—not from asking the model to be more careful.

Disclosure + limits

Internal execution recordings, selectors, repositories, and product screens cannot be published. “Zero false bug reports” refers to the reviewed full-product program represented by this case, not a universal guarantee for all future agent runs.

CASE / 02

Restoring trust after nineteen red days

2026
Anonymized B2B sales intelligence platform
Six CI runners
Shared staging backend

Claim under review

A red suite is useful only when the team can distinguish product failure from infrastructure noise.

19 red days21 failures0 new bugs
Evidence manifest
  • Every failing scenario reproduced in a live browser before classification.
  • Failure timing compared against page hydration, backend response delay, and concurrent runner load.
  • Known product defects separated from environment-load and timing failures.
  • Post-change runs reviewed for restored signal rather than a single lucky green build.
Systemic change

Fix the topology, not each symptom.

The investigation traced misleading timeouts to a shared staging environment under six-runner load. Timeout floors and execution behavior were tuned at the architecture level instead of weakening individual assertions.

Disclosure + limits

The raw CI logs, workflow files, and environment details are private. “Zero new product bugs” is limited to the failures reviewed in this nineteen-day streak; known defects remained classified separately.

CASE / 03

Finding failures no single monitor could see

2026
Anonymized B2B communications platform
Exception telemetry
Production session replay

Claim under review

A successful browser state can coexist with a failed internal operation.

2 years2,473 errors43 users / 90d
Evidence manifest
  • Exception telemetry established frequency and server-side failure shape.
  • Session replay established what affected users actually saw and did.
  • Source-level tracing connected the visible success state to the failing internal call.
  • A controlled retest overturned the first plausible diagnosis before the verdict was published.
Systemic change

Use two lenses and force them to agree.

The investigation combined exception telemetry, session replay, source inspection, and live reproduction into a repeatable forensics loop. Each source covered blind spots left by the others.

Disclosure + limits

Customer identities, recordings, stack traces, source code, and feature names are omitted. The error and affected-user counts are drawn from the reviewed ninety-day window, while the underlying defect had existed for roughly two years.
